# NEON.DOC — отчёты и рабочие документы через локальную LLM

Настольное приложение для студента и бизнес-аналитика: модель (Qwen через Ollama) пишет **только содержание**
в JSON по жёсткой схеме, а оформление по ГОСТ собирает детерминированный код по шаблону .docx.
Поэтому документ каждый раз выглядит одинаково, а ошибки модели ловит валидатор и отправляет ей на исправление.

Всё работает локально: текст, голос (Whisper), расшифровки встреч — ничего не уходит в облако.

**Требования:** Windows 10/11 (есть сборка для macOS), [Ollama](https://ollama.com) с моделью
(по умолчанию `qwen3.6:27b`, задаётся в настройках), Miniconda, Microsoft Word — для превью и PDF.

## Установка

Готовые архивы — на странице [Releases](../../releases):
- **Windows** — `NEON.DOC-windows.zip`, внутри «WINDOWS — КАК УСТАНОВИТЬ.txt»;
- **macOS (Apple Silicon)** — `NEON.DOC-mac.zip`, внутри «МАК — КАК УСТАНОВИТЬ.txt»; установщик сам ставит
  Python, Ollama, модель под объём памяти и Whisper (MLX).

Из исходников: склонируй репозиторий и запусти `install_app.bat` (Windows) или `install_mac.command` (Mac).

## Личные данные — `profile.yaml`

ФИО, группа, префикс имени файла, преподаватель по умолчанию и роль модели для рабочих документов
хранятся в `profile.yaml` в корне проекта. Скопируй `profile.example.yaml` → `profile.yaml` и заполни.
Файл в `.gitignore`: свои данные в репозиторий не попадут. Так же не попадают папки с работами,
чатами, расшифровками, хранилищем и рабочими шаблонами (см. `.gitignore`).

## NEON.DOC (приложение)

1. Один раз: `install_app.bat` — ставит зависимости в conda-окружение `reportgen`.
2. Запуск: `run_app.bat` (или ярлык NEON.DOC.bat на рабочем столе) — откроется окно приложения.
   Если окно не стартует, в `neondoc.log` будет причина; запасной вариант — `python -m neondoc --browser`.

Внутри: галерея шаблонов (колесо мыши над карточкой листает страницы), мастер работы
«Задание → План → Текст → Готово», правка текста и таблиц, голос через Whisper, вложения (.docx/.pdf/аудио),
история работ с метриками «до/после», редактор шаблонов, чат с Qwen с контекстом работы.

Данные — обычные папки: `library/templates/<шаблон>/` (template.yaml + previews/*.png),
`works/<работа>/` (work.json, task.yaml, brief.md, outline.json, sections/, report.json, run_log.jsonl, .docx),
`chats/`, `settings.yaml`.

## Новое в версии 2

После обновления один раз запусти `update_app.bat` (доставит пакеты), потом как обычно `run_app.bat`.

- **Хранилище** — папка `Хранилище/` рядом с программой: `ВУЗ/<предмет>/<тип работы>`, `Работа/<тип документа>`,
  `Входящие`, `_Корзина` (удалённое не стирается). Загрузка перетаскиванием, поиск по тексту docx/pdf/xlsx,
  перенос файлов мышью на папки, конвертация в PDF/Word/TXT. Собранная работа сама копируется в свой предмет.
- **Расшифровка** — аудио и видео → текст с таймкодами и участниками (Whisper + sherpa-onnx). Клик по таймкоду
  перематывает запись, участников можно переименовать. Qwen делает конспект, протокол, вопросы, требования, AS-IS.
  Расшифровку можно выгрузить в Word/PDF/TXT, добавить во вложения работы или обсудить в чате.
- **Разметка** — редактор скриншотов: рамки с номерами, стрелки, овалы, выноски, текст разными шрифтами, маркер,
  скрытие данных пикселями, прожектор, обрезка, слои, легенда «1 – …» для ТЗ, пресеты стиля. Сохраняет PNG
  и проект (`.annot.json`) — картинку можно открыть и поправить позже. Можно сразу отправить рисунком в работу.
- **Чат с Qwen** — прикрепляй любые файлы: docx, pdf, xlsx, pptx, txt, картинки (Qwen их видит), аудио и видео
  (сначала расшифруются). Большие файлы: в контекст попадают фрагменты, похожие на вопрос. Режим «Думать».
  Любой ответ — в Word / PDF / TXT.
- **Оформление** — 5 тем: Пиксель-мир (4 сезона × 5 времён суток, автосмена по часам и месяцу, «RTX»-свет),
  Неон 80-х, Тушь и спираль, Тихий офис, Графит. Настройки → Оформление.

Модели для разделения по участникам (~33 МБ) скачиваются с GitHub при первой расшифровке в `models/diarization/`.

## Конвейер из командной строки

Модель пишет только содержание в JSON по жёсткой схеме. Оформление собирает код по шаблону `templates/misis_report.docx`, собранному из эталонного отчёта МИСИС (`reportgen/make_template.py`).

```
templates/misis_report.docx  титул эталона с {{заполнителями}} + его стили, поля, колонтитул
reportgen/schema.py          что заполняет модель (Outline, Section, TextPart) и что ты (Meta)
reportgen/validate.py        правила: ошибки -> модели на исправление, предупреждения -> тебе
reportgen/llm.py             Ollama /api/chat: format=схема, think=false, temperature=0, до 3 попыток
reportgen/pipeline.py        plan -> write -> render
reportgen/render.py          JSON -> .docx, без модели
reportgen/make_template.py   пересобрать шаблон, если поменялся эталон
prompts/system.md            правила стиля для модели
tasks/<работа>/              task.yaml + brief.md + figures/*.png
```

## Установка (один раз)

`setup.bat` создаёт conda-окружение `reportgen` и ставит 4 пакета. Ollama должна быть запущена.

## Работа

1. Создай папку `tasks\имя_работы` и положи туда `task.yaml` (титул, скопируй из примера) и `brief.md` (задание из методички + факты о предприятии).
2. `run_plan.bat tasks\имя_работы`: модель пишет план (`outline.json`). **Прочитай его и поправь руками.** Это точка, где логика остаётся за тобой.
3. `run_write.bat tasks\имя_работы`: модель пишет разделы по одному, валидатор возвращает ошибки на исправление. Готовые разделы лежат в `sections\NN.json`. Если раздел не нравится, удали его файл и запусти снова: перепишется только он.
4. Положи схемы из draw.io в `figures\<id>.png` и запусти `run_render.bat`. Без PNG в документе будет жёлтая заглушка.
5. Открой .docx и вычитай. Всё, что модель не знала, отмечено жёлтым `[уточнить: …]`, список лежит в `review.txt`.

Правки титула вносятся в `task.yaml` и применяются через `run_render.bat`, модель для этого не нужна.

## Цифры «до/после»

`run_log.jsonl` пишет по каждому вызову время, токены, номер попытки и ошибки. Метрики для кейса:
- время от `brief.md` до готового .docx против времени, которое ушло на сданную ЛР;
- доля разделов, принятых с первой попытки (`attempt == 1 and ok`);
- число `[уточнить]` и ручных правок после рендера.


## Чего пока нет

- «Продолжение таблицы N»: длинная таблица переносится с повтором шапки (`tblHeader`), но строку «Продолжение таблицы» Word автоматически не ставит.
- Формулы и листинги кода (по договорённости в v1 не нужны).

## Рабочие документы (Шаблоны → вкладка «Работа»)

Шаблоны рабочих документов (описание робота, отчёт по обследованию, архитектурное решение и т. п.) —
это корпоративные документы, поэтому **в репозиторий они не входят**. Положи свои в `library/worktpl/<имя>/`
по описанию ниже, и они появятся на вкладке «Работа».

1. Шаблоны → «▣ РАБОТА» → карточка → «▶ Новый документ».
2. В «Материалы для Qwen» — своими словами, что известно, плюс файлы, выгрузки и записи встреч (аудио/видео расшифруются сами).
3. «✦ ЗАПОЛНИТЬ ЧЕРЕЗ QWEN» — каждый раздел отдельным запросом, таблицы приходят таблицами.
   Чего нет в материалах — `[уточнить: …]` + вопрос в «? ВОПРОСЫ» (список для встречи с заказчиком).
   Разделы, которые ты правил руками, при повторном заполнении не трогаются.
4. «✓ ПРОВЕРКА» — пустые разделы, незаполненные поля, для описания робота — требования к оформлению.
5. «▼ СОБРАТЬ» — Word / PDF / TXT, для описания робота ещё ZIP для Confluence. Копия кладётся в
   `Хранилище/Работа/<Описания роботов | Архитектура | Отчеты по обследованию>`.

Шаблоны лежат в `library/worktpl/<имя>/`: `spec.yaml` (поля, разделы, подсказки для Qwen, куда вписывать в .docx),
`template.docx`, `rules.md`. Новый шаблон того же вида = новая папка со `spec.yaml`.
Документы — `wdocs/<id>/` (doc.json, materials, figures, out). Командная строка: `python wdoc.py --help`.
